# ERP Ver2.9 全系统统一设计原则

> **适用范围**：Ver2.9 及后续 rc 开发（005 生产工单、007 下一步按钮、009 售后维修、006 库存深化等）。  
> **目标用户**：小型数控设备厂，约 10 人使用。  
> **核心目标**：复杂业务简单化、工人操作简单、系统计算简单、老板能看懂结果。  
> **项目路径**：`C:\Users\Administrator\Documents\ERP`

后续开发不要只看单个功能，要从 **系统结构、业务逻辑、员工操作、计算模式、模块边界、数据流转、权限、页面交互** 等方面统一考虑。

---

## 一、总体原则

1. ERP 不是越复杂越好，优先适配小型数控设备厂（约 10 人）。
2. 系统按真实业务分清楚：**销售、采购、生产、库存、财务、售后**。
3. 员工页面要简单：工人只填**事实**，不填复杂金额和系统字段。
4. 系统计算要简单：尽量只按**确认后的单据**计算库存、应收、应付。
5. 列表只显示**关键字段**，复杂字段放到详情。
6. 每个模块只负责**一件事**，不要一个页面混太多业务。
7. 后续功能优先增加 **「下一步按钮」** 和 **流程提示**，让员工不用猜下一步去哪里。
8. 不要把 **生产、现货销售、售后维修** 混在一个流程里。
9. 当前阶段不要做：复杂 MRP、复杂排产、复杂批次、复杂成本算法、复杂审批流。
10. **先做简单可用闭环，再逐步细化。**

## 二、全系统业务主线

系统后续应尽量收敛为以下几条主线。

### 1. 现货/配件销售

```
销售订单 → 销售出库 → 应收款 → 收款
```

**适用**：

- 配件销售
- 物料销售
- 维修件销售
- 已有库存的成品销售
- 不需要车间生产的商品

### 2. 生产整机/定制设备

```
销售订单 → 生产工单 → 生产领用 → 成品入库 → 销售出库 → 应收款 → 收款
```

**适用**：

- 整机设备
- 定制机型
- 需要车间装配/加工的产品
- 需要 BOM 和机型成本管理的成品

### 3. 采购入库

```
采购单 → 采购入库 → 应付款 → 付款
```

**适用**：

- 原材料采购
- 配件采购
- 外购件采购

### 4. 售后维修（后续单独模块）

```
维修工单 → 维修配件出库 → 收费结算 → 应收款 → 收款
```

**适用**：

- 客户机器坏了
- 工人带配件上门维修
- 收配件费 + 人工费
- 保内免费维修
- 保外收费维修

## 三、模块边界

后续开发严格区分模块职责：

| 模块 | 职责 | 不参与 |
|------|------|--------|
| **销售订单** | 记录客户要买什么、数量、金额、业务类型和状态 | 不直接扣库存、不直接收款 |
| **销售出库** | 记录实际发了什么货；**确认后**库存减少 | 不替代生产工单 |
| **生产工单** | 记录车间生产进度 | 不直接扣库存、不直接生成应收 |
| **生产领用** | 记录生产用了哪些材料；**确认后**原材料库存减少 | 不替代销售出库 |
| **成品入库** | 记录生产完成的成品入库；**确认后**成品库存增加 | 不自动生成应收 |
| **采购单** | 记录向供应商买什么、数量、金额和状态 | 不直接增加库存 |
| **采购入库** | 记录实际到货；**确认后**库存增加 | 不替代应付款登记逻辑 |
| **售后维修工单** | 后续单独设计：报修、派工、配件、人工费、结算 | 不塞进生产工单 |
| **应收款** | 记录客户欠多少、已收多少、未收多少 | 不与业务单据重复累计 |
| **应付款** | 记录欠供应商多少、已付多少、未付多少 | 不与业务单据重复累计 |
| **库存汇总** | 只看库存计算结果 | 原则上不手动改库存 |

## 四、员工操作方式

### 工人只需要看 / 做

- 今天做什么
- 做几台
- 领了哪些料
- 完成几台
- 点 **开始 / 完成 / 取消**

### 工人不要填

- 成本金额
- 应收金额
- 应付金额
- 库存金额
- 财务状态
- 系统计算字段
- 复杂编码

### 页面按钮尽量统一

`新增` · `查看` · `编辑` · `确认` · `开始` · `完成` · `取消` · `删除`

### 每个页面顶部要有通俗说明

- 当前页面**管什么**
- **不管什么**
- **下一步去哪里**

### 每个详情页尽量显示「下一步操作」

| 来源页面 | 建议下一步 |
|----------|------------|
| 销售订单 | 去销售出库 / 去生产工单 |
| 生产工单 | 去生产领用 / 去成品入库 |
| 采购单 | 去采购入库 |
| 应收款 | 登记收款 |
| 维修工单 | 添加配件 / 结算收费 |

## 五、系统计算模式

系统计算必须 **简单、稳定**：

1. **草稿**不参与库存、应收、应付计算。
2. **已确认**才参与计算。
3. **已取消**不参与计算。
4. **已完成**保留计算结果。
5. **删除**原则上只允许草稿或已取消的数据。
6. 修改已确认单据时，要考虑**差额回滚或重新计算**，不能重复累计。
7. 库存只由确认后的 **入库 / 出库 / 领用 / 成品入库** 计算。
8. 应收只由确认后的 **销售订单、维修结算** 等来源生成或更新。
9. 应付只由确认后的 **采购单** 生成或更新。
10. 财务收付款只**冲减**应收应付，不要和业务单据重复计算。

## 六、状态规则

各模块状态尽量统一，避免每个页面一套状态。

### 建议常用状态

`草稿` · `待确认` · `已确认` · `进行中` · `部分完成` · `已完成` · `已取消`

### 计算规则

| 状态 | 是否参与计算 |
|------|----------------|
| 草稿 | 否 |
| 已确认 / 进行中 / 部分完成 / 已完成 | 是（按业务规则） |
| 已取消 | 否 |
| 删除 | 仅允许草稿 / 已取消 |

## 七、业务类型建议（后续）

销售订单建议增加或保留 **「业务类型」** 概念：

| 业务类型 | 系统提示下一步 |
|----------|----------------|
| 现货/配件销售 | 下一步 → **销售出库** |
| 需要生产 | 下一步 → **生产工单** |
| 售后维修 | 下一步 → **维修工单** |

> **注意**：若当前 rc 任务范围不包含业务类型字段实现，只写入设计建议，不强行开发。

## 八、页面结构原则

所有业务页面尽量统一结构：

1. 顶部说明提示  
2. 统计卡片  
3. 搜索筛选  
4. 简洁列表  
5. 查看详情  
6. 新增/编辑弹窗  
7. 下一步按钮  
8. 状态操作  

### 列表只显示关键字段

编号 · 日期 · 往来单位 · 产品/物料 · 数量 · 金额 · 状态 · 操作

完整字段放 **详情**，不要把列表撑得太复杂。

## 九、005 生产工单专项遵守

### 生产工单只用于

- 车间生产
- 整机装配
- 定制设备
- 需要 BOM / 机型成本管理的成品

### 生产工单不用于

- 只卖配件
- 只卖物料
- 现货销售
- 售后维修 / 上门维修
- 配件费 + 人工费收费业务

### 005 当前范围

- 补齐易用性与业务边界说明  
- **不实现**售后维修模块  
- **不自动**扣库存、不自动生成生产领用/成品入库  

详见：`docs/worklog/reports/ver29_rc4_production_work_order_20260628_001741.md` 及补充报告 `ver29_rc4_production_work_order_fix_20260628_003710.md`。
