## 一、总体结论

### 结论：**有条件可以进入试运行**

**原因概述：**

从 Ver1.4 局域网档案管理，到 Ver2.8 销售/采购/库存/应收应付基础闭环，再到 Ver2.9 老板看板、单据关联、下一步按钮、售后维修、库存类型、表格优化与转出库/转入库，**系统已具备 10 人左右小型数控机床设备企业「日常基础业务」所需的主要模块**。本轮只读检查：`dotnet build` 成功、`run_ver29_regression` Overall PASS、页面检查全 PASS、8787 HTTP 200、正式 App exe 存在。

但系统仍是 **「能用版 / 试运行版」**，不是成熟企业级 ERP。以下事项未完成前，**不宜当作「可直接全面正式使用」**：

1. **rc18-rc19 人工浏览器验收**（转出库/转入库、表格显示、权限账号）尚未在本轮评估中替代人工点验。
2. **尚未打 Ver2.9 阶段性最终 tag**，版本边界未正式封存。
3. **`D:\冠誉制造ERP\Data` 尚未备份**，一旦正式录真实数据，丢失风险为 P0。
4. **真实业务口径**（库存汇总 vs 实物、应收应付 vs 财务收支、收款明细 vs 财务流水）需在 1–2 周真实单据中验证。
5. **JSON 文件存储 + 多人浏览器并发**无数据库级锁，长期并发编辑存在覆盖风险。

**试运行范围建议：**

| 范围 | 建议 |
|------|------|
| 人员 | 管理员 1 人 + 销售/采购/仓库/财务各 1 人，共 3–5 人小范围 |
| 可优先使用 | 供应商/客户/物料档案、销售订单→转出库→应收、采购单→转入库→应付、库存汇总参考、合同预览打印 |
| 谨慎使用 | 生产领用/成品入库（需人工核对 BOM 与实物）、财务收支（与应收应付登记收款口径分离）、售后维修（不扣库存） |
| 暂勿作为唯一依据 | 库存汇总（无流水台账）、首页部分旧表（档案参考口径）、售后配件库存、负库存场景 |

## 二、当前系统已具备能力

### 1. 基础资料：供应商、客户、物料

- 完整 CRUD、搜索、Excel 导入、CSV 导出、批量增删（Ver1.7+）
- 物料含库存类型、安全库存、默认仓库、是否库存物料、固定成本价等（rc16/rc17）
- 删除链路保护：供应商→物料→BOM→机型成本（Ver2.7）
- 子账号按模块权限控制菜单与 API（Ver2.2）

### 2. 销售：销售订单、销售出库、销售订单转出库

- 销售订单保存后自动生成应收（Ver2.8）
- 销售出库确认后扣库存（已确认单据参与 BuildStockMap）
- rc19：**转出库**按钮，已确认订单预填销售出库，可出库数量默认，无可转数量提示
- rc6/rc19：下一步按钮与流程提示并存

### 3. 采购：采购单、采购入库、采购单转入库

- 采购单保存后自动生成应付
- 采购入库确认后增加库存；成品设备入库有提示不建议直接入整机（rc17）
- rc19：**转入库**按钮，已确认采购单预填采购入库，可入库数量默认

### 4. 生产：BOM、机型成本、生产领用、成品入库

- BOM/机型成本：材料成本实时按物料价核算，CSV 导入导出（Ver2.3–2.4）
- 生产领用确认扣原材料库存；成品入库确认增成品库存
- **生产工单**（rc4）：有独立页面/API，仅记录进度，**不自动扣库存、不自动生成领用/入库单**
- 销售订单可跳转建生产工单（需车间生产的设备路径）

### 5. 库存：库存汇总、库存类型、安全库存、默认仓库、库存状态

- 只读汇总：采购入库 + 成品入库 − 销售出库 − 生产领用（已确认单据）
- rc16/rc17：库存类型、安全库存、库存状态（缺货/偏低/正常）、筛选与参考导出
- 销售出库/生产领用库存不足：**提醒 + 确认后可保存**，不硬拦截（rc17）
- **未做**：多仓库、移动加权平均、库存流水/台账、自动预警推送

### 6. 财务：应收、应付、收付款明细、财务收支、期初余额

- 应收/应付与订单/入库/出库/售后关联；收付款明细更新已收/已付状态
- **收款/付款明细不会自动写入财务收支流水**（文档与 UI 已说明）
- 财务收支三套账户（公户/公司私户/个人私户）、期初余额、月度统计
- rc3.5/rc3.6：操作影响预检、删除保护、收付款明细删除重算

### 7. 合同：合同资料、合同管理、预览、打印

- 18 类合同资料、设备明细/配件/配置/技术参数动态行（Ver2.5）
- HTML 范本占位符替换、金额中文大写、复制/作废/打印

### 8. 售后：售后维修基础、维修费用应收基础

- 售后维修工单：报修、派工、配件明细、费用汇总、状态流转（rc9–rc11）
- 手动「生成应收款」；**配件只记费用，不扣库存**
- 操作记录与权限收口（rc11）

### 9. 系统：权限、子账号、测试数据、清空保护、操作记录

- admin + 子账号模块级权限；操作影响预检（Ver2.8-rc3.5）

## 三、系统优点

### 1. 对小型数控机床设备企业的匹配度 — **较高**

- 覆盖「卖设备/配件 → 采购 → 生产领用/成品入库 → 出库 → 应收应付 → 合同」主链路
- BOM + 机型成本贴合设备制造企业核价习惯
- 库存类型区分原材料/外购配件/成品设备/维修备件，符合行业物料形态
- 生产工单与现货出库分流说明清晰，避免小厂误用复杂流程

### 2. 模块覆盖 — **满足当前基础使用**

Ver1 档案 + Ver2 业务 + Ver2.9 体验增强，已超出「只有供应商客户物料」阶段，形成可跑通的基础闭环。

### 3. 本地部署与局域网 — **适合现阶段**

- 无云依赖、数据在厂内 D 盘，符合中小厂对数据掌控的需求
- 单 exe + 浏览器，IT 成本低；10 人规模单机部署合理

### 4. 测试数据导入导出 — **价值高**

- 回归、培训、AI 协助排查均可复用 XLSX 总表
- 预检查机制降低误导入风险

### 5. 回归脚本与页面检查 — **价值高**

- `run_ver29_regression.ps1` 一键 build + Git Guard + API Health + Pages
- `check_ver29_pages.ps1` 覆盖 40+ 关键词（含 rc16–rc19）
- 本轮检查：**Overall PASS**，全部页面标记 PASS

### 6. 库存类型设计 — **价值中等偏高**

- 在不做多仓库/加权平均前提下，用类型 + 安全库存 + 状态给出「缺货/偏低」参考
- 成品设备采购入库提示、销售出库库存提醒，降低误操作概率

### 7. rc18-rc19 表格优化 — **价值中等**

- col-money/col-qty 分列、长文本 ellipsis，降低一线员工阅读成本
- 对 daily 使用体验有直接改善

### 8. 转出库/转入库 — **价值高**

- 减少销售/采购重复录入，是 Ver2.9 最易感知效率提升之一
- 仍走原有保存接口，未改库存核心，风险可控

### 9. 清空数据保护与权限 — **安全价值高**

- 二次密码、确认文字、清空前备份、操作影响预检
- 子账号默认无权限，需 admin 分配

### 10. 文档、台账、版本记录 — **价值高**

- README、VERSION、安装说明、任务总表、执行台账、reports 形成可追溯开发史
- 利于 ChatGPT/人工复核与后续排期

## 四、系统缺点

必须正视的短板（整体视角）：

1. **仍是「能用版」**：无完整 ERP 级别的审批流、总账、成本核算引擎、报表中心。
2. **页面字段仍偏多**：Business.html 等业务页字段多、表格宽，rc18 仅缓解未根治；Contract/BOM 等复杂页仍学习成本高。
3. **单据流转仅基础版**：转出库/转入库是预填 + 打开新增，无强锁定、无部分出库状态机、无重复出库硬拦截。
4. **生产工单不完整**：有登记页但不联动领用/入库/缺料，车间管理仍需人工串联多张单据。
5. **无库存流水/台账**：无法按时间追溯「某物料何时入何时出」，审计与对账依赖单据列表人工查。
6. **库存预警不完整**：有安全库存与状态展示，无主动提醒、无采购建议、无邮件/消息。
7. **售后维修不扣库存**：配件费可记、可生成应收，但库存账与实物可能不一致。
8. **应收应付 vs 财务收支需人工对齐**：登记收款不自动写财务流水，试运行中易出现「应收已收清但财务账未记」。
9. **多人同时操作**：JSON 整文件读写，后写覆盖先写，无乐观锁/版本号（除部分 UpdatedAt 校验）。
10. **JSON 长期积累风险**：单据/日志增多后，单次读写变慢；无索引、无分页后端，大列表靠前端过滤。
11. **备份恢复需制度化**：功能已有，但无强制日程；未备份 Data 就正式使用是最大缺口之一。
12. **真实业务暴露面**：负库存、重复出入库、订单改价后历史单据、BOM 改价后已保存工单成本等，需跑真实单验证。

## 五、主要风险点

### P0 高风险（影响正式使用或数据安全）

| # | 风险 | 说明 |
|---|------|------|
| 1 | **正式使用前未备份 Data** | 当前尚未备份；一旦录真实数据，磁盘/误操作/恢复失败后果严重 |
| 2 | **清空数据误操作** | 虽有二次密码，admin 仍可能误点；开始真实数据后应禁止随意清空 |
| 3 | **真实数据与测试数据混用** | 测试导入与正式单据同库，易造成编号/金额/库存混乱 |
| 4 | **JSON 文件损坏或丢失** | 断电、杀毒、手动编辑、同步盘冲突可能导致 JSON 不可用 |
| 5 | **多人同时编辑同一单据** | 无数据库事务，可能后保存覆盖先保存 |

### P1 中风险（效率或部分准确性）

| # | 风险 | 说明 |
|---|------|------|
| 6 | **单据重复录入/重复出入库** | 转出库/转入库有基础提示，无强防重；同一订单可多次出库 |
| 7 | **应收应付与财务口径不一致** | 登记收款 ≠ 财务收支；老板看板与财务账可能对不上 |
| 8 | **库存汇总与实物偏差** | 无流水台账；负库存仅提醒；售后/调整无专门入口 |
| 9 | **权限配置不当** | 子账号权限过多或过少，导致误删或无法操作 |
| 10 | **浏览器缓存旧页面** | 更新 App 后未 Ctrl+F5，员工看到旧 UI/旧 JS |
| 11 | **Windows 进程占用** | ERP.exe 运行时无法覆盖 bin\Debug，影响开发 build/publish |

### P2 低风险（体验、文档、后续优化）

| # | 风险 | 说明 |
|---|------|------|
| 12 | **表格仍复杂** | rc18 改善但未全面覆盖 Contract/BOM/工单等 |
| 13 | **第二台电脑访问/防火墙** | 需确认主机 IP、8787 端口、防火墙入站规则 |

## 七、是否建议现在继续做 rc20

### 明确回答：**建议暂停 rc20 及之后主线开发**

**原因：**

1. **当前已达到阶段性可试运行程度** — Ver2.8 业务闭环 + Ver2.9 体验与流转增强已足够支撑小范围真实使用。
2. **继续开发会增加不稳定性** — 库存流水、预警、工单联动、006 深化均触及核心或数据模型，试运行前不宜叠加。
3. **应先用真实业务跑 1–2 周** — 才能知道是表格问题多、流转问题多、还是财务口径问题多。
4. **后续优化应按反馈排序** — 避免「开发认为重要」与「车间每天痛」脱节。
5. **生产工单深化、库存台账、多仓库、移动加权平均都不应现在硬上** — 设计原则与 rc15 006 评审已明确 006 最后做、不做加权平均。

## 九、老板视角结论

### 1. 现在这个系统能干什么

- 管供应商、客户、物料档案；开销售订单、一键转出库发货；开采购单、一键转入库收货
- 看库存大概有多少、哪些偏低；管应收应付谁欠钱、谁欠供应商
- 做 BOM 和机型成本核价；做合同预览打印；登记售后维修和收费
- 局域网多台电脑共用一个账；数据在自己 D 盘，不依赖云

### 2. 还不能干什么

- 不能像大 ERP 一样自动排产、自动算加权成本、分仓库调拨
- 不能查完整库存流水账；售后修机器不会自动扣配件库存
- 财务收支和登记收款不是一回事，要人工对
- 多人同时改同一张单，可能互相覆盖
