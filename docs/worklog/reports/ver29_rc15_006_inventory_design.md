## 1. 当前库存现状

### 1.1 已有业务模块（前端 + 后端）

| 模块 | 页面位置 | 主要 API / 逻辑 | 当前行为摘要 |
|------|----------|-----------------|--------------|
| 采购入库 | `Business.html` → purchase-inbound | 确认后写入采购入库 JSON | 按 **物料 ID** 增加「物料」类库存，单价取入库价 |
| 销售出库 | Business → sales-outbound | 确认后扣减 | 成品走 BOM/机型成本 ID；非成品走物料 ID；**无库存不足校验** |
| 生产领用 | Business → production-pick | 确认后扣减 | 按物料 ID 扣减；**无库存不足校验** |
| 成品入库 | Business → finished-inbound | 确认后增加 | 按 BOM/机型成本 ID 增加「成品」类库存，单价取 unitCost |
| 库存汇总 | Business → warehouse-stock | `GET /api/stocks`、`/api/stocks/summary` | 只读展示；`BuildStockMap()` 聚合 |

### 1.2 当前数据模型要点

**物料主数据 `Material`（`Program.cs`）** 现有字段：Id、Code、Supplier、NameSpec、QuantityUnit、TaxPrice、NoTaxPrice、PriceType、Note、Status 等。**尚无** StockType、IsInventoryItem、默认仓库、成本方式等库存深化字段。

**库存汇总 `BuildStockMap()`** 当前逻辑：

- 采购入库（已确认）→ `StockAddMaterial`，ItemType = `"物料"`
- 成品入库（已确认）→ `StockAdd`，ItemType = `"成品"`，ItemId = ModelCostId 或 BomId
- 销售出库（已确认）→ 成品/物料分别扣减
- 生产领用（已确认）→ 物料扣减
- 聚合键：ItemType + ItemId（**不按仓库、不按库存类型、不按批次**）
- 仓库名固定为 `"默认仓库"`
- **允许负库存**（数量可为负，无拦截）
- 成本：按聚合后 `CostAmount / |Quantity|` 推算展示单价

**售后维修工单（rc9/rc10/rc11）**：配件明细仅作金额计算与应收关联；**不扣库存、不自动应收**（应收需手动生成）。

### 1.3 当前约束（本设计阶段必须遵守）

1. **不能直接改库存核心计算**（`BuildStockMap`、`StockAdd*` 等）——须等用户确认规则后再分阶段实施。
2. **不能直接执行 006**（inbox 中的 rc5 仓库类型深化实现任务）。
3. **本文件只做设计**，为后续开发任务与迁移兼容方案提供输入。
4. 旧 JSON 数据须兼容：不得在未出迁移方案前批量改写历史库存文件（见 inbox 006 任务要求）。

## 2. 数控机床小厂库存类型设计

面向「数控机床小厂」场景，建议至少区分 **7 种库存类型**（StockType 枚举候选）：

| 序号 | 库存类型 | 代码建议 | 典型存放物 | 说明 |
|------|----------|----------|------------|------|
| 1 | 原材料 | `RAW` | 钢材、板材、型材、毛坯、外协加工件坯料 | 机加工前的基础材料，采购入库主来源 |
| 2 | 外购配件 | `PURCHASED_PART` | 电机、丝杆、导轨、电气柜、数控系统、刀库 | 整件外购、可单独销售或装配进整机 |
| 3 | 标准件 | `STANDARD` | 螺丝、螺母、轴承、密封圈、标准紧固件 | 规格化、用量大、单价低，可独立领用 |
| 4 | 成品设备 | `FINISHED_MACHINE` | CK6150、VMC850 等整机、已完工可交付设备 | 对应 BOM/机型成本，成品入库与销售出库主对象 |
| 5 | 维修备件 | `SERVICE_PART` | 售后常用件、易损件、现场维修专用库存 | **是否与外购配件合并，待用户确认** |
| 6 | 低值易耗品 | `CONSUMABLE` | 切削液、砂纸、手套、包装材料、办公耗材 | 可纳入库存但通常不做严格成本结转 |
| 7 | 其他 | `OTHER` | 暂无法分类或过渡期物料 | 默认兜底，后续可再归类 |

### 2.1 类型与现有 ItemType 的关系（设计意图）

| 现有 BuildStockMap ItemType | 深化后建议 |
|----------------------------|------------|
| `"物料"` | 细分为 RAW / PURCHASED_PART / STANDARD / CONSUMABLE / OTHER（由物料 StockType 决定） |
| `"成品"` | 对应 FINISHED_MACHINE（由 BOM/机型成本或物料 IsFinishedGood 标记） |

半成品（WIP）本厂 rc5 inbox 曾提及，**本设计暂不单独列为第 8 类**；若用户确认需要「半成品库」，可在阶段 2 扩展为 `SEMI_FINISHED`，或先用 OTHER + 备注过渡。

## 3. 物料主数据需要增加或明确的字段

以下为 **设计字段**（不写代码），实施时加在 `Material` 或独立扩展表，须兼容旧数据默认值。

| 字段 | 类型建议 | 用途 | 默认值 | 是否必填 |
|------|----------|------|--------|----------|
| **StockType** | 枚举字符串 | 库存分类：RAW / PURCHASED_PART / STANDARD / FINISHED_MACHINE / SERVICE_PART / CONSUMABLE / OTHER | `OTHER`（旧数据）或按 NameSpec/PriceType 惰性推断 | 深化启用后：新建必填；旧数据可空→读时默认 |
| **IsInventoryItem** | bool | 是否纳入库存汇总与出入库校验 | `true` | 否；服务类、纯费用项设为 false |
| **IsFinishedGood** | bool | 是否成品（整机） | `false` | 否；与 StockType=FINISHED_MACHINE 应一致 |
| **IsServicePart** | bool | 是否售后维修专用件 | `false` | 否；与 StockType=SERVICE_PART 应一致 |
| **SafetyStock** | decimal | 安全库存，低于时预警 | `0` | 否 |
| **DefaultWarehouse** | string | 默认仓库名 | `"默认仓库"` | 否；多仓库阶段再必填 |
| **CostMethod** | 枚举 | 固定 / 最近采购 / 加权平均 / 手动（见第 7 节） | `MANUAL` 或 `FIXED`（与现有物料价一致） | 否 |
| **Remark** | string | 库存相关备注（存放位置、批次规则说明等） | 空 | 否 |

### 3.1 字段一致性规则（设计）

- `IsFinishedGood=true` ⇒ StockType 应为 `FINISHED_MACHINE`（或允许过渡期仅 bool 优先）。
- `IsServicePart=true` ⇒ StockType 应为 `SERVICE_PART`（若用户确认维修件单独类型）。
- `IsInventoryItem=false` ⇒ 不参与 BuildStockMap，出入库单选物料时可选过滤或警告。

### 3.2 旧数据兼容策略（概要，详细迁移另文）

- 读取时：缺 StockType → 按现有 ItemType（物料/成品）映射为 OTHER 或 FINISHED_MACHINE。
- 不批量改 JSON；用户编辑保存或导入时再写入新字段。

## 4. 库存汇总规则

### 4.1 汇总维度（必须同时满足）

后续库存汇总 **至少** 按以下维度区分，**不可混并**：

1. **物料 ID**（或成品 BOM/机型成本 ID）
2. **库存类型 StockType**
3. **仓库 DefaultWarehouse / 单据仓库**
4. **必要时**：批次号、采购单号、入库单号（阶段 6 以后可选）

### 4.2 合并与禁止合并规则

| 场景 | 规则 |
|------|------|
| 同名不同 ID | **禁止合并**；每个 ID 独立一行库存 |
| 同名同 ID 但 StockType 不同 | **禁止合并**（同一 ID 不应有两种类型；若发生视为数据错误，需修正主数据） |
| 成品设备 vs 外购配件 | **禁止合并**；ItemType/StockType 不同 |
| 维修备件 vs 普通销售配件 | **待用户确认**：方案 A 合并为 PURCHASED_PART；方案 B 独立 SERVICE_PART 汇总 |
| 跨仓库 | **禁止合并**；同 ID 同类型在不同仓库各一行 |

### 4.3 展示与 API 设计意向

- `GET /api/stocks` 增加可选 query：`stockType`、`warehouseId`、`itemId`
- 汇总页支持：按类型 Tab / 筛选、按仓库筛选、显示安全库存预警
- 总数量：可按类型分组小计 + 全局合计（是否合计 CONSUMABLE 待用户确认）

## 5. 出入库影响规则

以下均为 **目标规则设计**；实施前须用户确认勾选（见第 9 节）。

### 5.1 采购入库

| 库存类型 | 影响 |
|----------|------|
| 原材料 RAW | ✅ 增加库存 |
| 外购配件 PURCHASED_PART | ✅ 增加库存 |
| 标准件 STANDARD | ✅ 增加库存 |
| 低值易耗品 CONSUMABLE | ✅ 增加库存（可选：仅数量不记金额） |
| 维修备件 SERVICE_PART | ✅ 增加库存（若启用独立类型） |
| 成品设备 FINISHED_MACHINE | **待用户确认**：通常应走「成品入库」而非采购入库；若允许采购整机入库，须强制 StockType=FINISHED_MACHINE |
| 其他 OTHER | ✅ 增加库存 |

### 5.2 销售出库

| 库存类型 | 影响 |
|----------|------|
| 成品设备 FINISHED_MACHINE | ✅ 减少库存 |
| 外购配件 PURCHASED_PART | ✅ 减少库存 |
| 标准件 STANDARD | ✅ 减少库存 |
| 原材料 RAW | 一般不走销售出库；若卖余料 **待用户确认** |
| 维修备件 | 若合并配件类型则同 PURCHASED_PART |
| 库存不足 | **待用户确认**：允许负 / 禁止 / 提醒不拦截（见第 6 节） |

### 5.3 生产领用

| 库存类型 | 影响 |
|----------|------|
| 原材料 RAW | ✅ 减少库存 |
| 外购配件 PURCHASED_PART | ✅ 减少库存 |
| 标准件 STANDARD | ✅ 减少库存 |
| 成品 / 低值易耗 | 一般不领用；例外 **待用户确认** |
| 库存不足 | **待用户确认**（负库存策略） |

### 5.4 成品入库

| 规则 | 说明 |
|------|------|
| 对象 | FINISHED_MACHINE（BOM/机型成本 ID） |
| 数量 | 增加成品库存 |
| 关联 BOM/机型成本 | **待用户确认**：必须 / 可选 / 保持现状 |
| 单价 | 取自成品入库 unitCost（机型成本快照） |

### 5.5 售后维修用料（候选，暂不接代码）

| 项目 | 设计 |
|------|------|
| 状态 | rc9 售后工单 **当前不扣库存**；本设计仅作候选 |
| 候选单据 | 「售后维修件领用」：从 SERVICE_PART 或 PURCHASED_PART 扣减 |
| 触发时机 | 工单「完成」或「结算」时扣减 **待用户确认** |
| 是否纳入库存 | **待用户确认**：暂不纳入 / 纳入维修领用 / 后续单独模块 |

## 6. 负库存规则候选

| 方案 | 行为 | 优点 | 缺点 |
|------|------|------|------|
| **A：允许负库存** | 确认出库/领用时不做数量拦截 | 小厂录单不卡流程；与 **当前系统行为一致** | 库存可能长期不准；财务对账困难 |
| **B：禁止负库存** | 可用量不足则拒绝保存/确认 | 库存严谨、账实相符 | 必须先补入库或调账，操作步骤多 |
| **C：提醒但不拦截** | 保存成功但提示「已超可用库存」并写操作记录 | 兼顾灵活与可见提醒 | 仍可能产生负库存 |

**推荐（设计阶段）：** 小厂前期采用 **方案 C**；流程稳定后可配置切换为 **方案 B**。若用户希望零改动上线，可暂选 **方案 A** 与现状一致。

适用场景建议：

- 销售出库、生产领用：共用同一配置项 `StockNegativePolicy` = allow | block | warn
- 采购入库、成品入库：不涉及负库存

## 7. 成本价规则候选

| 方案 | 说明 | 适用 |
|------|------|------|
| 1. 固定成本价 | 物料主数据维护固定单价；出入库带该价 | 小厂、品种少 |
| 2. 最近采购价 | 以最近一次采购入库价覆盖或展示 | 原材料、配件 |
| 3. 移动加权平均 | 每次入库更新加权成本 | 财务要求严、后期再上 |
| 4. 手动指定成本价 | 出库/入库单上手工填 cost | 灵活、与现成品入库 unitCost 类似 |

**推荐（当前阶段）：**

- 保持 **「物料成本价 / 机型成本快照 + 单据单价」** 为主（接近方案 1 + 4）。
- **暂不实施移动加权平均**；等库存类型与出入库闭环稳定后，单开「阶段 6：成本价深化」任务。
- CONSUMABLE 类可只跟踪数量，金额可选。

## 8. 与应收 / 应付 / 财务的边界

| 边界 | 说明 |
|------|------|
| 006 库存深化 **不得** 直接修改 | 应收核心计算、应付核心计算、财务核心计算、收付款核销逻辑 |
| 保持现状 | 销售订单 → 应收、采购单 → 应付的生成规则不变 |
| 006 允许影响范围 | 库存分类字段、库存汇总展示、出入库校验与提醒、库存金额 **展示**（非财务过账） |
| 售后维修 | 继续「手动生成应收」；维修领用扣库存若启用，**不自动**改应收金额 |
| 后续联动 | 库存价值 → 财务科目、成本结转、毛利报表等 **必须单独开任务**，不在 006 范围内 |
